- 🔄 **In Progress** — Code exists, UI/behavior being refined

## Phase 9: Security, Permissions & Digital Signatures 🔄
- [x] **Task 9.1** — Password encryption & permissions: Document Open Password (AES-256 or AES-128); Permissions Password (Master/Owner); Printing (None/LowRes/HighRes); Changes Allowed (None/Page in/out/rotation/Fill&Sign/Comment&Fill/Any-Except-Extract); Text/graphic copy enable; Screen reader enable; Decrypt on open prompt; "Remove Protection" requires permissions password — **overstated.** There is no AES-128 option: `EncryptionStrength` is only `{Rc4_128, Aes256}` (`crates/youpdf-core/src/protect.rs:35-41`). The app's default AES-256 revision-6 output cannot be re-opened by the app's own decrypt path — `open_protected` (`crates/youpdf-core/src/protect.rs:205`) delegates to `lopdf::Document::decrypt`, and lopdf 0.34 supports only V1-2/RC4, as the repo's own `crates/youpdf-core/examples/encrypt_verify.rs` says in its header comment. The Protect dialog has an "Open password" and a "Permissions password" field, but "Remove Protection" accepts any password that opens the file and never checks the owner password, so it does not "require permissions password". The permission choices are eight independent checkboxes (`crates/youpdf-app/src/app/pages_ui.rs:52-65`) rather than a "Changes allowed" enum, and printing is not split into None/LowRes/HighRes.
- [x] **Task 9.2** — Redaction (two-phase destructive engine): Phase 1: Mark (drag rectangles, translucent red fill/dark red border, hover preview, redaction properties: fill color/overlay text/font/color); Phase 2: Apply (warning modal: "permanently destroys underlying text/images, cannot be undone"); core engine: intersects with text characters/path vectors (permanently deletes); intersects with images (burns in pixels); rasterizes complex vectors if needed; removes overlapping annotations; "Sanitize Document" strips metadata, hidden text, embedded files, bookmarks, comments, form actions, deleted object revisions — **partly done.** Redaction is applied per text-showing operation, not per character: an overlapping `Tj`/`TJ` is dropped whole (`crates/youpdf-core/src/redact/surgery.rs:97-110`). `sanitize()` removes only `/Metadata`, `/OpenAction`, `/AA`, `/Names/JavaScript` and most of `/Info` (`crates/youpdf-core/src/organize.rs:812-816`); it does not strip hidden text, embedded files, bookmarks, comments, form actions or revisions, and it explicitly keeps attachments.
- [ ] **Task 9.3** — Digital signatures & certificates (PAdES/PKCS#7): Certificate Manager: import PKCS#12 (.p12/.pfx) with password; Create Self-Signed (name, org, email, country, validity); Sign Document: place signature field on canvas, select certificate, Appearance (name, date/time, reason, location, DN info + optional visual signature graphic); Hash with SHA-256, encrypt with private key, embed PKCS#7 into `/ByteRange`; Validation: notification bar "All digital signatures are valid" (green) or "Signature was modified after signing" (red); Certificate details dialog (validity, issuer, timestamp) — **engine only, no interface.** The core engine is real (`crates/youpdf-core/src/signature.rs`: `from_pkcs12`, `create_self_signed`, `sign()` writing `/ByteRange` + SHA-256 + CMS, `validate_signatures`), but the application has no UI for it: `sign_open` is declared (`crates/youpdf-app/src/app.rs:1420`), initialised (`crates/youpdf-app/src/app.rs:1836`) and set by the Tools menu (`crates/youpdf-app/src/app.rs:7209`) but never read — no window is ever drawn, and the app never calls any signing function. The "All digital signatures are valid" banner does not exist.

## Current State Summary (October 2026)

**The engine is broadly complete; the interface is not.** The core crates implement most of the operations this plan describes, but several phases are only half-wired, and six tasks are not implemented at all:
- ❌ Task 4.2 — content elements can be selected and moved on paper, but not on screen: there is no hit-test dispatch, no resize or rotation handles and no drag-to-move or scale.
- ❌ Task 5.2 — the eraser has Segment mode only; the Stroke mode is unreachable.
- ❌ Task 5.5 — no custom-stamp dialog, no signature-creator window, no stored-signatures list (visual signature placement is real).
- ❌ Task 9.3 — the signing engine exists in `youpdf-core`, but the application has no signing window and never calls it.
- ❌ Task 12.2 — the comparison engine produces a text-diff report; there are no view modes, no options, no side-by-side or overlay.
- ❌ Task 13.1 — the batch queue lists file names only: no table, no per-file status, no progress bar, no ETA, no cancel.
- ❌ Task 14.2 — the i18n dictionary exists but is wired to the Tools dropdown only.

Other phases are complete in the core and partly complete in the interface: Phase 4 (the caret is a plain text field, with no arrow-key navigation), Phase 5 (four shape kinds, no fill and no dash picker), Phase 12 (measurement is one drag rectangle, calibration reuses the last drag), Phase 14 (no "Follow System" theme, no "Last docs" startup, no Comments section), Phase 9 (no AES-128, no Master/Owner distinction, "Remove Protection" accepts any opening password), Phase 10 (Word exact layout uses `w:framePr`, not `w:txbxContent`), Phase 11 (no OCR page range; mode 3 is "text + images"), Phase 8 (watermark is text-only; "Remove Watermark" only sees this app's own decorations) and Phase 6 (no push-button action, no date picker, no password masking, no list-box multi-select).

**French localization (🌐):** the `i18n` dictionary holds ~110 entries and `t()` returns French for them, but only the Tools dropdown and the "Language" label are routed through it; the status bar, the inspector, the sidebars, the dialogs and the toolbars remain in hardcoded English.
